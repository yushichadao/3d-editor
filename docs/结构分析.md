## 二、坐标系与轴向约定（重要）

应用对外呈现的坐标系与 Three.js 内部坐标系不同，这是阅读代码时最容易混淆之处。

- **用户视角（UI 标签）**：**Z 轴向上**（高度方向）。轴向配色为 **X 蓝（前后 / 深度）、Y 红（左右）、Z 绿（上下 / 高度）**。地面为 **XZ 平面**，`y = 0` 为物体落地的高度基准。
- **实现细节**：Three.js 默认 **Y-up**，代码中 `axisColors` 内部仍为 `x=红、y=绿、z=蓝`；但通过**重映射轴标签**（`makeAxisLabel`）向用户呈现 "Z-up / X蓝·Y红·Z绿" 的约定：
  - `xLabel` 位于世界 +X，文本 `'Y'`、颜色 `axisColors.x`（红）→ 用户眼中"红色 = 左右 = Y"；
  - `yLabel` 位于世界 +Y（竖直向上），文本 `'Z'`、颜色 `axisColors.y`（绿）→ 用户眼中"绿色 = 上下 = Z"；
  - `zLabel` 位于世界 +Z，文本 `'X'`、颜色 `axisColors.z`（蓝）→ 用户眼中"蓝色 = 前后 = X"。
  - 相关代码见 ~L1971–L1973、L1990–L2007；箭头方向则保持 Three.js 原生（+X/+Y/+Z）。
- **落地处理**：`seatOnGround`（L2371）将几何体底面平移到 `y = 0`，保证新建物体"站在地面上"。

> 结论：文档（使用说明书、README）统一采用 **Z-up / X蓝·Y红·Z绿** 的用户视角描述；代码内部是 Y-up + 标签重映射。二者并不矛盾，只是表述层级不同。

## 四、全局状态与关键数据流

- **核心对象**：`scene`、`camera`、`renderer`、`controls`（OrbitControls）、`raycaster`、`SELECTED`（当前选中集）、`CLIPBOARD`、`state`（工具/主题/语言/视图等）。
- **主题系统**：一组主题对象（neon / sunset / forest / gray / light 等）通过 `applyThemeObj` 把 CSS 变量写入 `:root`，全站配色随之切换；说明书卡片使用 `--bg-manual`、`--control-bg` 等变量，自动适配明暗。
- **多语言**：`language/*.js` 提供 `zh-CN / en / ja / zh-TW` 词条；说明书正文 `docs/*.md` 亦按语言分文件加载。
- **事件主链路**：`pointerdown/move/up`/`touch*` → `touchPointer` (1863) → 工具分发（`setTool` 体系）→ 几何/变换/历史 → 渲染循环 `animate` (10379) 持续呈现。

## 五、渲染循环与交互入口

`animate` (10379) 是每帧唯一入口：更新 `controls`、ghost 预览位置、便签层、窗口自适应，并 `renderer.render`。所有业务修改都通过修改场景图与状态，由该循环统一呈现，避免散落的 `render()` 调用。

## 六、说明书与便签系统（本次新增模块）

位于脚本末端（L10554–L10998），是一套轻量 Markdown 渲染与便签体系：

- **渲染**：`mdInline` (10554) 解析行内标记，`parseBlocks` (10568) 分块，`renderBlock` (10590) 逐块出 HTML；`>` 引用卡片在暗色下使用主题化背景与可读文字。
- **说明书 / 指南**：`openManual` (10627)、`loadManual` (10877) 按当前语言异步加载 `docs/*.md` 并渲染；`buildToc` (10885) 生成目录；`openGuide` (10902) 打开操作指南。
- **便签**：`renderNotes` (10712) 管理说明书内便签列表（含全选/批量删除，删除经 `showConfirm` 自定义确认弹窗）；`closeSticky` (10771) 关闭浮动便签窗口。
- **高亮**：`wrapText` (10604) / `unwrapHighlights` (10603) 实现搜索/选择高亮的包裹与还原。
